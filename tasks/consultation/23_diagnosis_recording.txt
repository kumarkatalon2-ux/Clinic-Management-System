================================================================================
1. OBJECTIVE STATEMENT
================================================================================

Implement comprehensive diagnosis recording system enabling doctors to document 
diagnoses, maintain active problem list, track disease progression, and provide 
clinical decision support for differential diagnosis. System must support ICD-10 
coding, hierarchical problem management (chronic conditions, acute episodes, 
complications), disease stage tracking, and longitudinal problem trending. Enable 
full diagnosis lifecycle from suspected diagnosis → confirmed diagnosis → resolved 
or chronic disease. Maintain complete audit trail of problem list changes and 
integrate with clinical decision support for evidence-based diagnosis recommendations.

Expected Outcome:
- Complete diagnosis lifecycle management (suspected → confirmed → resolved)
- Active problem list maintained and searchable
- ICD-10 code assignment and management
- Disease stage and severity tracking
- Problem trending and comorbidity analysis
- Differential diagnosis support via clinical decision support
- HIPAA-compliant diagnosis history and audit trail

================================================================================
2. BUSINESS LOGIC EXPLANATION
================================================================================

DIAGNOSIS LIFECYCLE:

1. Suspected Diagnosis Creation
   - During consultation, doctor suspects specific diagnosis
   - Findings and symptoms support suspected diagnosis
   - System suggests ICD-10 codes matching suspected diagnosis
   - Doctor selects ICD-10 code (or searches by description)
   - Certainty level set to POSSIBLE or SUSPECTED
   - Differential diagnosis noted (alternative possibilities)
   - Evidence for diagnosis documented (exam findings, test results)

2. Diagnosis Confirmation
   - Additional testing performed to confirm diagnosis:
     ├─ Laboratory tests (blood cultures for infection, glucose for diabetes)
     ├─ Imaging studies (X-ray, CT, ultrasound)
     ├─ Procedures (biopsy, endoscopy, colonoscopy)
     ├─ Specialist consultation (cardiologist, neurologist)
     └─ Clinical observation (symptoms resolve, improve, worsen)
   - Doctor confirms diagnosis based on test results
   - ICD-10 code confirmed and locked
   - Certainty level changed to CONFIRMED or PROBABLE
   - Supporting evidence documented (lab values, imaging findings)

3. Active Problem List Management
   - Confirmed diagnoses added to active problem list
   - Patient's current active problems displayed:
     ├─ Chronic diseases (diabetes, hypertension, asthma)
     ├─ Acute conditions (pneumonia, urinary tract infection, migraine)
     ├─ Recent surgeries (post-operative status)
     ├─ Complications (secondary diagnoses)
     └─ Rule-outs (diagnoses ruled out by testing)
   - Each problem includes:
     ├─ ICD-10 code and description
     ├─ Onset date (when problem started)
     ├─ Status (active, resolved, chronic, episodic)
     ├─ Severity (mild, moderate, severe, critical)
     ├─ Stage (for staged diseases like cancer)
     └─ Last updated date

4. Chronic Disease Tracking
   - For chronic diagnoses (diabetes, hypertension):
     ├─ Disease duration tracked
     ├─ Control status monitored (well-controlled, partially-controlled, uncontrolled)
     ├─ Complication status tracked (diabetic neuropathy, hypertensive nephropathy)
     ├─ Treatment regimen documented (medications, lifestyle changes)
     ├─ Monitoring frequency defined (visit intervals, lab test frequency)
     └─ Preventive measures documented (flu vaccines, cancer screenings)
   - Longitudinal trending:
     ├─ Disease severity trending (improving, stable, worsening)
     ├─ Lab value trends (glucose trending down = better control)
     ├─ Vital sign trends (BP trending down = better control)
     ├─ Medication effectiveness tracking
     └─ Complication emergence tracking

5. Disease Complication Recording
   - When complications develop:
     ├─ New ICD-10 code added for complication
     ├─ Linked to parent diagnosis (diabetic neuropathy linked to diabetes)
     ├─ Recorded as active problem
     ├─ Treatment plan modified
     └─ Monitoring intensity increased
   - Complication hierarchy maintained:
     ├─ Parent diagnosis easily identifiable
     ├─ Related complications grouped
     ├─ Triggering diagnosis clear
     └─ Complication onset tracked

6. Rule-Out Diagnoses
   - Diagnoses ruled out by testing documented:
     ├─ Suspected diagnosis (e.g., pneumonia suspected)
     ├─ Testing performed (chest X-ray: normal, negative culture)
     ├─ Diagnosis ruled out (not pneumonia)
     ├─ Status set to RULED_OUT
     ├─ Reasoning documented
     └─ Date ruled out recorded
   - Maintains differential diagnosis history
   - Prevents future duplicate testing/investigations

7. Diagnosis Resolution
   - For acute conditions (infection, injury):
     ├─ Patient recovers from acute problem
     ├─ Symptoms resolve
     ├─ Status changed to RESOLVED
     ├─ Resolution date recorded
     ├─ Outcome documented (fully recovered, partially recovered)
     └─ Shifted to historical/resolved problem list
   - For chronic conditions (diabetes, hypertension):
     ├─ Status remains CHRONIC/ONGOING
     ├─ Managed long-term with monitoring
     ├─ Complications tracked separately
     └─ Never truly "resolved" (ongoing management)

8. Problem List Updates & Maintenance
   - Active problem list reviewed at each visit:
     ├─ Verification that problems still accurate
     ├─ Status updates (resolved problems archived)
     ├─ New problems added (from current consultation)
     ├─ Problem severity reassessed
     ├─ Treatment effectiveness evaluated
     └─ Care plan adjusted based on current status
   - Automated alerts for concerning patterns:
     ├─ Rapidly worsening condition (escalation)
     ├─ Uncontrolled chronic disease (intervention alert)
     ├─ New complication development (alert)
     ├─ Multiple related problems (care coordination alert)
     └─ Drug interactions with chronic medications (safety alert)

DIAGNOSIS TYPES:

Primary Diagnosis:
  - Most significant/most important diagnosis
  - Typically the chief complaint reason for visit
  - Single primary diagnosis per encounter
  - Example: "Acute bacterial bronchitis"

Secondary Diagnosis:
  - Additional diagnoses found during same encounter
  - May relate to primary diagnosis or be independent
  - Multiple secondary diagnoses possible
  - Example: "Acute sinusitis" (found during bronchitis eval)

Complication/Sequela:
  - Diagnosis resulting from prior diagnosis
  - Related to primary diagnosis, not independent
  - Usually develops after primary diagnosis onset
  - Example: "Diabetic neuropathy" (complication of diabetes)

Differential Diagnosis:
  - Alternative possible diagnoses being considered
  - Not yet confirmed, still being ruled out
  - Used during diagnostic workup
  - Example: "Pneumonia vs bronchitis vs asthma exacerbation"

Rule-Out Diagnosis:
  - Diagnosis definitively excluded by testing
  - Documentation prevents unnecessary future testing
  - Example: "Myocardial infarction ruled out (negative troponin)"

3. DATA MODEL DEFINITION
================================================================================

TABLE: diagnoses
  diagnosis_id (UUID, PK)
  patient_id (UUID, FK → patients)
  icd10_code (VARCHAR, indexed) - ICD-10 code
  diagnosis_name (VARCHAR) - full diagnosis name
  diagnosis_type (ENUM: PRIMARY, SECONDARY, COMPLICATION, DIFFERENTIAL, RULED_OUT)
  status (ENUM: SUSPECTED, POSSIBLE, PROBABLE, CONFIRMED, CHRONIC, RESOLVED, RULED_OUT)
  onset_date (DATE) - when problem started
  resolution_date (DATE, nullable) - when problem resolved
  severity (ENUM: MILD, MODERATE, SEVERE, CRITICAL)
  is_active (BOOLEAN, default true) - on active problem list?
  is_chronic (BOOLEAN) - ongoing chronic disease?
  is_complication_of (UUID, FK → diagnoses, nullable) - links to parent diagnosis
  stage (VARCHAR, nullable) - disease stage (e.g., "Stage 2 hypertension")
  laterality (ENUM: BILATERAL, LEFT, RIGHT, null) - side-specific if applicable
  documented_in_consultation (UUID, FK → consultations)
  documented_by_doctor (UUID, FK → doctors)
  last_updated_date (DATE)
  updated_by_doctor (UUID, FK → doctors)
  control_status (ENUM: WELL_CONTROLLED, PARTIALLY_CONTROLLED, UNCONTROLLED, null)
  monitoring_frequency (VARCHAR, nullable) - e.g., "monthly", "quarterly"
  created_at (TIMESTAMP)
  updated_at (TIMESTAMP)
  metadata (JSONB) - additional diagnosis-specific data

TABLE: diagnosis_evidence
  evidence_id (UUID, PK)
  diagnosis_id (UUID, FK → diagnoses)
  evidence_type (ENUM: SYMPTOM, EXAM_FINDING, LAB_RESULT, IMAGING_FINDING, PROCEDURE_RESULT, CLINICAL_OBSERVATION)
  evidence_description (TEXT) - "fever 38.5°C", "cough productive of green sputum", "WBC 12,000"
  evidence_value (VARCHAR, nullable) - numerical value if applicable
  unit (VARCHAR, nullable) - unit of measurement (°C, mmHg, mg/dL)
  supporting_diagnosis (BOOLEAN, default true) - does this support diagnosis?
  documented_at (TIMESTAMP)
  test_id (UUID, nullable) - links to lab test or imaging study
  created_at (TIMESTAMP)

TABLE: diagnosis_comorbidities
  comorbidity_id (UUID, PK)
  primary_diagnosis_id (UUID, FK → diagnoses)
  comorbid_diagnosis_id (UUID, FK → diagnoses)
  relationship_type (ENUM: DIRECTLY_CAUSED_BY, RISK_FACTOR_FOR, COMPLICATES, UNRELATED)
  clinical_significance (ENUM: LOW, MEDIUM, HIGH)
  documented_at (TIMESTAMP)

TABLE: diagnosis_treatment_plans
  plan_id (UUID, PK)
  diagnosis_id (UUID, FK → diagnoses)
  treatment_approach (VARCHAR) - e.g., "antibiotic therapy", "lifestyle modification"
  medications (JSONB) - list of prescribed medications
  monitoring_requirements (TEXT) - lab tests, vital signs to track
  specialist_referrals (JSONB) - specialist consultations needed
  follow_up_interval (VARCHAR) - when to follow up
  expected_resolution_timeframe (VARCHAR, nullable) - e.g., "7-10 days"
  created_at (TIMESTAMP)
  updated_at (TIMESTAMP)

TABLE: diagnosis_history
  history_id (UUID, PK)
  patient_id (UUID, FK → patients)
  icd10_code (VARCHAR) - historical diagnosis
  diagnosis_name (VARCHAR)
  onset_date (DATE)
  resolution_date (DATE, nullable)
  status (ENUM: RESOLVED, RECURRING, RECURRING_EPISODIC)
  episodes_count (INT) - number of times this diagnosis has occurred
  last_episode_date (DATE, nullable)
  total_duration (VARCHAR) - total time affected by this condition
  archived_date (DATE) - moved to history
  created_at (TIMESTAMP)

TABLE: differential_diagnoses
  differential_id (UUID, PK)
  consultation_id (UUID, FK → consultations)
  icd10_code (VARCHAR)
  diagnosis_name (VARCHAR)
  likelihood_ranking (INT) - 1 = most likely, 2 = second, etc.
  clinical_reasoning (TEXT) - why doctor suspects this diagnosis
  supporting_findings (TEXT)
  tests_needed_to_confirm (TEXT)
  tests_needed_to_rule_out (TEXT)
  status (ENUM: CONSIDERED, PROBABLE, CONFIRMED_PRIMARY, RULED_OUT)
  status_update_date (DATE)
  status_update_reason (TEXT)
  created_at (TIMESTAMP)

TABLE: icd10_codes_reference
  icd10_id (UUID, PK)
  icd10_code (VARCHAR, UNIQUE)
  description (VARCHAR)
  long_description (TEXT)
  category (VARCHAR) - broad disease category
  subcategory (VARCHAR) - specific disease type
  is_billable (BOOLEAN)
  is_unspecified (BOOLEAN)
  requires_7th_character (BOOLEAN)
  valid_age_range (VARCHAR, nullable)
  related_codes (VARCHAR, array) - similar/related ICD-10 codes
  male_only (BOOLEAN, default false)
  female_only (BOOLEAN, default false)
  excludes (VARCHAR, array) - diagnoses that exclude this code
  excludes_after (VARCHAR, array) - diagnoses that require this code
  notes (TEXT)
  created_at (TIMESTAMP)
  updated_at (TIMESTAMP)

================================================================================
5. WORKFLOW DESCRIPTION - STEP-BY-STEP PROCESS FLOW
================================================================================

NEW DIAGNOSIS SUSPECTED & CONFIRMED:

Step 1: Suspected Diagnosis Identification
  └─ During consultation, doctor suspects specific diagnosis
  └─ Patient findings support suspected diagnosis
  └─ System suggests ICD-10 codes matching findings:
     ├─ Cough + fever + infiltrate on X-ray → bronchitis/pneumonia ICD-10 codes
     └─ System displays top 5-10 matching diagnoses
  └─ Doctor reviews suggested diagnoses and selects most likely
  └─ ICD-10 code selected or searched manually

Step 2: Evidence Documentation
  └─ Supporting evidence for diagnosis documented:
     ├─ Symptoms (productive cough, fever, chills)
     ├─ Examination findings (bilateral wheezing, fever)
     ├─ Lab results (elevated WBC count)
     ├─ Imaging findings (infiltrate on chest X-ray)
     └─ Clinical context (recent illness exposure)
  └─ Each finding tagged as "supports diagnosis"
  └─ Evidence database updated

Step 3: Differential Diagnosis Consideration
  └─ Doctor considers alternative diagnoses:
     ├─ Pneumonia (more serious, infiltrate on X-ray)
     ├─ Asthma exacerbation (wheezing present)
     └─ Other respiratory infections
  └─ Ranked by likelihood (primary, secondary, tertiary)
  └─ Differential diagnoses recorded

Step 4: Testing to Confirm Diagnosis
  └─ If diagnosis certain:
     ├─ Status set to CONFIRMED
     ├─ Diagnosis added to active problem list immediately
     └─ Treatment plan initiated
  └─ If diagnosis uncertain:
     ├─ Additional tests ordered:
     │  ├─ Sputum culture (culture)
     │  ├─ Blood culture (if pneumonia suspected)
     │  ├─ Repeat chest X-ray (if worsening)
     │  └─ Spirometry (if asthma exacerbation suspected)
     ├─ Diagnosis set to SUSPECTED status
     ├─ Follow-up appointment scheduled
     └─ Provisional treatment may be initiated

Step 5: Diagnosis Confirmation & Problem List Update
  └─ Test results received and reviewed:
     ├─ Sputum culture positive for bacterial organism
     ├─ Blood cultures negative (localizes to respiratory)
     ├─ Diagnosis confirmed as bacterial pneumonia
  └─ Diagnosis status updated to CONFIRMED
  └─ ICD-10 code updated to specific pneumonia type (bacterial)
  └─ Added to active problem list
  └─ Severity assessment:
     ├─ Vital signs stable → MODERATE
     ├─ Hypoxia developing → SEVERE
     └─ Sepsis criteria met → CRITICAL
  └─ Treatment plan escalated based on severity

Step 6: Active Problem List Management
  └─ Diagnosis now visible in patient's active problem list:
     ├─ Ranked by severity and impact
     ├─ Primary diagnosis (pneumonia) appears first
     ├─ Secondary problems (chronic hypertension, diabetes) below
     └─ Related complications identified
  └─ All care team members can see active problems
  └─ Alerts triggered if needed:
     ├─ Critical findings (sepsis alert)
     ├─ Drug interactions (antibiotic with current meds)
     ├─ Allergy conflicts
     └─ Care coordination issues

CHRONIC DISEASE MANAGEMENT (ongoing):

Step 1: Diagnosis Documentation
  └─ Patient diagnosed with chronic disease (diabetes, hypertension)
  └─ Status set to CHRONIC (ongoing)
  └─ Never resolved, permanently on active problem list

Step 2: Disease Stage & Control Assessment
  └─ For diabetes:
     ├─ Type: Type 1 vs Type 2
     ├─ Stage: Early (no complications) vs Advanced (multiple complications)
     ├─ Control status: Well-controlled (HbA1c < 7) vs Uncontrolled (HbA1c > 8)
     └─ Complications: None, neuropathy, nephropathy, retinopathy
  └─ For hypertension:
     ├─ Stage: Stage 1 (130-139) vs Stage 2 (≥ 140)
     ├─ Control status: Well-controlled (< 130/80) vs Uncontrolled
     └─ Complications tracked

Step 3: Longitudinal Monitoring
  └─ Lab values tracked over time:
     ├─ Diabetes: HbA1c trending (goal < 7%, patient at 7.8%)
     ├─ Hypertension: BP readings trending (fluctuating, not well-controlled)
     ├─ Lipids: Lipid panel trending (LDL not at goal)
     └─ Kidney function: Creatinine, eGFR (monitoring for disease progression)
  └─ Alerts generated:
     ├─ Worsening control (HbA1c rising, not declining)
     ├─ New complication development (protein in urine = new nephropathy)
     ├─ Treatment resistance (BP not responding to current meds)
     └─ Missed monitoring (due for annual lab work)

Step 4: Complication Management
  └─ When complication develops:
     ├─ New ICD-10 code recorded (diabetic neuropathy)
     ├─ Linked to parent diagnosis (Type 2 diabetes)
     ├─ Added to active problem list
     ├─ Treatment plan created for complication
     └─ Monitoring intensity increased
  └─ System alerts for complication risk:
     ├─ Diabetes + proteinuria → nephropathy risk (monitor renal function)
     ├─ Diabetes + stocking-glove paresthesias → neuropathy confirmed
     ├─ Diabetes + vision changes → retinopathy risk (refer to ophthalmology)
     └─ Hypertension + chest pain → cardiac risk (EKG, troponin)

Step 5: Preventive Care Management
  └─ For chronic diseases, preventive care tracked:
     ├─ Diabetes: Annual eye exam (ophthalmology), foot exam (podiatry)
     ├─ Hypertension: Annual ECG, lipid panel, kidney function
     ├─ Vaccinations due (flu, pneumococcal for elderly)
     ├─ Cancer screenings (colonoscopy, mammogram per guidelines)
     └─ System generates preventive care reminders

Step 6: Ongoing Care Coordination
  └─ Multiple providers managing patient with chronic diseases:
     ├─ Primary care (overall coordination)
     ├─ Cardiology (hypertension, cardiovascular risk)
     ├─ Endocrinology (diabetes control)
     ├─ Nephrology (kidney disease if develops)
     ├─ Ophthalmology (eye disease screening)
     └─ All providers see unified problem list
  └─ Care coordination alerts:
     ├─ Conflicting treatment plans (different BP targets)
     ├─ Medication duplications or gaps
     ├─ Specialist recommendations not implemented
     └─ Monitoring gaps (labs not done on schedule)

DIAGNOSIS RESOLUTION (Acute Conditions):

Step 1: Infection/Acute Problem Resolved
  └─ Patient recovers from acute condition:
     ├─ Symptoms resolve (cough gone, fever resolved)
     ├─ Lab values normalize (WBC back to normal)
     ├─ Imaging improves (infiltrate clearing on X-ray)
     └─ Patient feeling well

Step 2: Doctor Documents Resolution
  └─ At follow-up visit, doctor confirms recovery:
     ├─ Reviews symptoms (patient reports no cough, feels good)
     ├─ Performs examination (lungs clear, no wheezing)
     ├─ Reviews repeat labs/imaging if done (clear)
     └─ Concludes problem resolved
  └─ Updates diagnosis status:
     ├─ Status changed to RESOLVED
     ├─ Resolution date recorded (2026-02-05)
     ├─ Outcome documented (fully recovered, no complications)
     └─ Diagnosis archived to history

Step 3: Problem List Updated
  └─ Resolved diagnosis removed from active problem list
  └─ Moved to historical/resolved problems
  └─ No longer triggers alerts or monitoring
  └─ Available in history if patient experiences recurrence

  │ Impact: Incorrect diagnoses recorded, coding errors
  │ Probability: MEDIUM
  │ Mitigation:
  │  ├─ Verify against official CMS database
  │  ├─ Monthly updates from authoritative source
  │  ├─ Code validation on entry
  │  ├─ Deprecation alerts for old codes
  │  └─ Periodic audits

  │ Impact: Missed diagnosis if CDS recommendations incorrect
  │ Probability: MEDIUM
  │ Mitigation:
  │  ├─ Evidence-based recommendations only
  │  ├─ Clinical advisors review
  │  ├─ Recommendations are advisory (not binding)
  │  ├─ Doctor retains full clinical authority
  │  └─ Regular accuracy monitoring

RISK 3: Chronic Disease Control Calculation Complexity
  │ Impact: Incorrect disease control assessment
  │ Probability: MEDIUM
  │ Mitigation:
  │  ├─ Define clear control criteria per disease
  │  ├─ Integrate evidence-based guidelines
  │  ├─ Automated calculation with manual override
  │  ├─ Regular validation against clinical standards
  │  └─ Feedback loop for accuracy

RISK 4: Comorbidity Over-Alerting
  │ Impact: Alert fatigue reduces clinical effectiveness
  │ Probability: MEDIUM
  │ Mitigation:
  │  ├─ Only high-significance alerts triggered
  │  ├─ Configurable alert thresholds
  │  ├─ Learning system (reduces false alerts)
  │  ├─ Feedback loop to improve
  │  └─ Clinician customization options
