OBJECTIVE
---------
Implement slot management system that generates, tracks, and manages all
available appointment slots based on clinic configuration, doctor schedules,
and resource availability.

BUSINESS LOGIC
--------------
Slot Management Purpose:

Slots are discrete time windows when appointments can be booked:

Doctor: Dr. Smith
Date: February 15, 2024
Operating Hours: 8am-5pm
Appointment Type: General Visit (30 minutes)
Buffer: 5 minutes before and after

Generated Slots (in 30-min increments with 5-min buffer):

Time Window | Available?
8:00am-8:35am | Check if free
8:30am-9:05am | Check if free
9:00am-9:35am | Check if free
... (continue through day)
4:30pm-5:05pm | Check if free (extends past 5pm close)

Why Slots Matter:

1. PERFORMANCE
   Pre-calculated slots faster than real-time availability checks
   
2. CONSISTENCY
   All doctors/rooms use same slot grid (standardized)
   
3. USER EXPERIENCE
   Users select from discrete slots (cleaner UI)
   vs. entering arbitrary times
   
4. RESOURCE COORDINATION
   Slots align with resource constraints
   
SLOT GENERATION
---------------
Slot Generation Algorithm:

FOR each clinic day (e.g., Feb 15, 2024):
  IF clinic closed on day:
    SKIP day
  
  FOR each doctor working that day:
    appointment_duration = 30 minutes
    buffer_before = 5 minutes
    buffer_after = 5 minutes
    total_slot_duration = 30 + 5 + 5 = 40 minutes
    
    clinic_start = 8:00am
    clinic_end = 5:00pm
    doctor_start = 8:00am (or doctor-specific)
    doctor_end = 5:00pm
    
    current_time = doctor_start
    WHILE current_time + appointment_duration <= doctor_end:
      slot = {
        time: current_time,
        duration: appointment_duration,
        doctorId: doctor.id,
        clinicId: clinic.id,
        date: Feb 15
      }
      ADD slot to slots table
      
      current_time += increment (usually 15 or 30 min)

Example Slot Generation for Dr. Smith, Feb 15:

Start: 8:00am
End: 5:00pm
Appointment Duration: 30 min
Increment: 30 min (could also be 15 min for finer granularity)

Generated Slots:
8:00am (end 8:30am)
8:30am (end 9:00am)
9:00am (end 9:30am)
9:30am (end 10:00am)
... continues every 30 minutes
4:30pm (end 5:00pm)
5:00pm (end 5:30pm) ← Extends past clinic hours (allowed if buffer goes past)

If appointment already exists 9-10am:
8:00am: AVAILABLE (ends 8:30am, before 9am start)
8:30am: AVAILABLE (ends 9:00am, meets 9am start exactly)
9:00am: UNAVAILABLE (conflicts with 9am existing)
9:30am: UNAVAILABLE (still within 9-10am)
10:00am: AVAILABLE (starts 10am, after existing ends)

SLOT DATA MODEL
---------------
Slots Table:

CREATE TABLE appointment_slots (
  id UUID PRIMARY KEY,
  clinic_id UUID NOT NULL,
  doctor_id UUID NOT NULL,
  appointment_type_id UUID NOT NULL,
  
  slot_date DATE,
  slot_time TIME,
  slot_duration_minutes INT,
  
  status VARCHAR(50),
  -- AVAILABLE, BOOKED, BLOCKED, UNAVAILABLE, CANCELLED
  
  appointment_id UUID,  -- FK to appointments (if booked)
  
  reason_if_blocked VARCHAR(255),
  -- "Doctor vacation", "Room maintenance", etc.
  
  created_at TIMESTAMP,
  updated_at TIMESTAMP,
  
  UNIQUE(clinic_id, doctor_id, slot_date, slot_time)
);

Slot Statuses:

AVAILABLE: Open for booking
  - Doctor available
  - Room available
  - No conflicts
  - Patient can book

BOOKED: Appointment exists
  - Appointment scheduled
  - Slot taken
  - Cannot book another

BLOCKED: Deliberately blocked
  - Lunch break
  - Staff meeting
  - Maintenance
  - Doctor lunch

UNAVAILABLE: Cannot be booked
  - Doctor not working
  - Clinic closed
  - Insufficient resources
  - Policy prevents

CANCELLED: Was booked, now cancelled
  - Patient cancelled
  - Clinic cancelled
  - Slot returned to availability

SLOT LIFECYCLE
--------------
1. GENERATION
   System generates slots (daily job, or on-demand):

   POST /slots/generate
   {
     "clinicId": "uuid-clinic",
     "startDate": "2024-02-01",
     "endDate": "2024-02-29",
     "appointmentTypeId": "uuid-type-general"
   }

   System generates all possible slots for February
   Example: 20 working days × 10 doctors × 16 slots/day = 3,200 slots

2. AVAILABILITY CHECK
   When patient requests availability:

   GET /slots/available
   ?clinicId=uuid-clinic
   &doctorId=uuid-doctor
   &date=2024-02-15
   &appointmentTypeId=uuid-type-general

   Response:
   [
     { time: "8:00am", status: "AVAILABLE", slotId: "slot-001" },
     { time: "8:30am", status: "AVAILABLE", slotId: "slot-002" },
     { time: "9:00am", status: "BOOKED", slotId: "slot-003" },
     ... etc
   ]

3. BOOKING
   When patient selects slot:

   POST /slots/slot-001/book
   {
     "patientId": "uuid-patient",
     "appointmentReason": "Annual checkup"
   }

   System:
   - Marks slot as BOOKED
   - Creates appointment record
   - Links slot to appointment
   - Sends confirmation

4. CANCELLATION
   When patient cancels:

   DELETE /appointments/appt-123

   System:
   - Marks appointment as CANCELLED
   - Updates slot status to AVAILABLE (or CANCELLED tracking)
   - Slot available for rebooking

5. EXPIRATION
   Old slots deleted (keep current + 1 year future):

   Nightly Job:
   DELETE FROM appointment_slots
   WHERE slot_date < TODAY - 1 year

OPTIMIZED SLOT RETRIEVAL
------------------------
Challenge: 3,200+ slots per month per clinic

Query: "Show available slots for Feb 15"

Naive Query (SLOW):
SELECT * FROM appointment_slots
WHERE clinic_id = ? AND date = ? AND status = 'AVAILABLE'
→ Could scan thousands of rows

Optimized Query (FAST):
CREATE INDEX (clinic_id, date, status)

SELECT * FROM appointment_slots
WHERE clinic_id = ? AND date = ? AND status = 'AVAILABLE'
→ Uses index, scans only available slots

Further Optimization:
Cache available slots in memory (Redis):

GET cache:slots:{clinicId}:{date}
→ If exists, return cached (sub-millisecond)
→ If not, query DB and cache for 1 hour

Invalidate cache when:
- Appointment booked
- Appointment cancelled
- Slot blocked/unblocked
- Schedule changed

SLOT MANAGEMENT FOR MULTIPLE APPOINTMENT TYPES
-----------------------------------------------
Different appointment types = different slot lengths:

General Visit: 30 minutes
Follow-up: 20 minutes
Procedure: 60 minutes
Consultation: 45 minutes

Each type generates its own slots:

Feb 15, Dr. Smith:

General Visit Slots (30 min):
8:00am, 8:30am, 9:00am, 9:30am, ..., 4:30pm (16 slots)

Follow-up Slots (20 min):
8:00am, 8:20am, 8:40am, 9:00am, 9:20am, ..., 4:40pm (24 slots)

Procedure Slots (60 min):
8:00am, 9:00am, 10:00am, ..., 4:00pm (9 slots)

When slot booked, affects different appointment types:

Book General 9:00am-9:30am:
- 9:00am-9:30am General: BOOKED
- 8:40am-9:00am Follow-up: Can still book (ends when General starts)
- 9:00am-10:00am Procedure: BOOKED (overlaps)

OVERBOOKING SLOT MANAGEMENT
----------------------------
Clinic allows 10% overbooking:

Total slots: 100
Overbooking slots: 10
Regular slots: 90

Slot Management:

Regular Slots (priority 1):
Booked first, system tries to avoid overbooked slots

Overbooked Slots (priority 2):
Only offered if no regular slots available

Flag on Slot:

CREATE TABLE appointment_slots (
  ... (existing columns)
  is_overbooked BOOLEAN DEFAULT false,
  overbooked_position INT  -- 1st overbooked, 2nd, etc.
);

When booking:

IF available_regular_slots > 0:
  USE regular slot
  is_overbooked = false
ELSE IF available_overbooked_slots > 0:
  USE overbooked slot
  is_overbooked = true
ELSE:
  OFFER waitlist
