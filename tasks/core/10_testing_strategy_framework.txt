UNIT TESTING
------------
Test individually: Functions, methods, classes

Framework: Jest (JavaScript) or equivalent

Structure: Given-When-Then (AAA pattern)

Example:
```javascript
describe('PatientService', () => {
  describe('createPatient', () => {
    it('should create a patient with valid data', () => {
      // GIVEN
      const patientData = {
        firstName: 'John',
        lastName: 'Doe',
        dateOfBirth: '1990-01-15'
      };
      
      // WHEN
      const result = patientService.createPatient(patientData);
      
      // THEN
      expect(result.id).toBeDefined();
      expect(result.firstName).toBe('John');
    });
    
    it('should throw error with missing firstName', () => {
      // GIVEN
      const patientData = { lastName: 'Doe' };
      
      // WHEN/THEN
      expect(() => patientService.createPatient(patientData))
        .toThrow('First name required');
    });
  });
});
```

INTEGRATION TESTING
-------------------
Test components together: API → Service → Database

Framework: Supertest (HTTP) + Jest

Example:
```javascript
describe('GET /api/v1/patients/:id', () => {
  it('should return patient with valid ID', async () => {
    // GIVEN
    const patientId = 'patient-123';
    const token = generateValidToken();
    
    // WHEN
    const response = await request(app)
      .get(`/api/v1/patients/${patientId}`)
      .set('Authorization', `Bearer ${token}`);
    
    // THEN
    expect(response.status).toBe(200);
    expect(response.body.data.id).toBe(patientId);
    expect(response.body.data.firstName).toBeDefined();
  });
  
  it('should return 404 for non-existent patient', async () => {
    const response = await request(app)
      .get('/api/v1/patients/invalid-id')
      .set('Authorization', `Bearer ${token}`);
    
    expect(response.status).toBe(404);
    expect(response.body.success).toBe(false);
  });
});
```

END-TO-END (E2E) TESTING
-----------------------
Test complete user workflows: UI → API → DB → UI

Framework: Cypress or Playwright

Scenario: Doctor views patient and prescribes medication

```javascript
describe('Doctor Prescription Workflow', () => {
  it('should prescribe medication to patient', () => {
    // Login as doctor
    cy.visit('https://clinic-saas.com/login');
    cy.get('[data-testid=email]').type('doctor@clinic.com');
    cy.get('[data-testid=password]').type('secure-password');
    cy.get('[data-testid=login-btn]').click();
    
    // Navigate to patients
    cy.get('[data-testid=nav-patients]').click();
    cy.get('[data-testid=patient-search]').type('John Doe');
    cy.contains('John Doe').click();
    
    // View medical record
    cy.get('[data-testid=tab-medical-record]').click();
    cy.contains('Prescription').should('be.visible');
    
    // Create prescription
    cy.get('[data-testid=btn-new-prescription]').click();
    cy.get('[data-testid=drug-name]').type('Amoxicillin');
    cy.get('[data-testid=quantity]').type('21');
    cy.get('[data-testid=frequency]').select('3 times daily');
    cy.get('[data-testid=btn-save]').click();
    
    // Verify prescription saved
    cy.contains('Prescription saved').should('be.visible');
    cy.contains('Amoxicillin').should('be.visible');
  });
});
```

PERFORMANCE TESTING
-------------------
Load Testing: How system behaves under load

Tool: Apache JMeter or Locust

Scenarios:

Baseline: Normal operations
- 100 concurrent users
- Typical load

Peak Load: Busy time
- 500 concurrent users
- Sustained for 10 minutes

Spike Test: Sudden surge
- 1000 concurrent users for 1 minute
- How quickly does system recover?

Stress Test: Breaking point
- Gradually increase load until failure
- At what point does system fail?
- Graceful degradation or crash?

Example test plan:
```
Phase 1: Ramp-up
  - 0 to 100 users over 5 minutes
  - Duration: 5 minutes
  
Phase 2: Sustained load
  - 100 concurrent users
  - Duration: 15 minutes
  
Phase 3: Spike
  - 100 to 500 users in 1 minute
  - Duration: 5 minutes
  
Phase 4: Ramp-down
  - 500 to 0 users over 5 minutes
  - Duration: 5 minutes
```

Performance Acceptance Criteria:
[ ] p50 response time < 500ms
[ ] p95 response time < 1000ms
[ ] p99 response time < 2000ms
[ ] Error rate < 0.1%
[ ] No memory leaks
[ ] CPU utilization < 70%
[ ] Database connections < 80% of pool

REGRESSION TESTING
------------------
Prevent old bugs from returning

Strategy:
- Every bug gets test case
- Test case added before fix
- Test case catches regression
- Run regression tests on every build

Example:
Bug: Prescription quantity could be negative
Fix: Add validation check
Test:
```javascript
it('should not allow negative quantity', () => {
  expect(() => prescription.validate({ quantity: -5 }))
    .toThrow('Quantity must be positive');
});
```
