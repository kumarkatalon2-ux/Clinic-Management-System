OBJECTIVE
---------
Implement a comprehensive authentication and authorization system supporting
multi-tenant clinic access, role-based access control (RBAC), and HIPAA/GDPR
compliance requirements.

BUSINESS LOGIC
--------------
User Roles in Clinic System:

1. SUPER ADMIN (SaaS Platform Level)
   - Platform administration
   - Clinic management
   - Billing oversight
   - System monitoring
   - Cannot access clinic data directly

2. CLINIC ADMIN (Per-Clinic)
   - Full control of clinic
   - Staff management
   - Configuration
   - Billing reconciliation
   - Access to all clinic data

3. DOCTOR / PRACTITIONER
   - View own patients
   - Create/update medical records
   - Write prescriptions
   - View appointments
   - Limited access scope

4. NURSE / CLINICAL STAFF
   - View assigned patients
   - Record vitals/observations
   - Assist with appointments
   - View patient history
   - Limited write access

5. RECEPTIONIST / FRONT DESK
   - Manage appointments
   - Patient scheduling
   - Check-in/check-out
   - Insurance verification
   - No clinical access

6. PATIENT (Self-Service Portal)
   - View own records
   - Book appointments
   - Message clinic
   - Request prescriptions
   - Billing information

7. BILLING STAFF
   - Manage invoices
   - Process payments
   - Insurance claims
   - Revenue reports
   - No clinical access

Authentication Flow:
1. User provides email + password
2. System validates credentials
3. Verify clinic_id/tenant_id association
4. Generate JWT with claims (user_id, clinic_id, roles, permissions)
5. Return access_token + refresh_token
6. Client includes token in Authorization header
7. API validates JWT on every request
8. Check permissions against required scope

SESSION MANAGEMENT
------------------
Access Token:
- Duration: 15 minutes
- Claims: user_id, tenant_id, clinic_id, roles, permissions_hash
- Signing: RS256 (asymmetric)
- Validation: On every API request

Refresh Token:
- Duration: 30 days
- Stored: Secure HTTP-only cookie (or encrypted localStorage)
- Rotation: Issue new refresh token on each use
- Revocation: On logout, password change, role change

Multi-Clinic Access:
- User can belong to multiple clinics
- Token includes primary clinic_id
- API allows clinic_id in request header to switch context
- Audit log tracks clinic context

PERMISSION STRUCTURE
--------------------
Granular Permissions (NOT roles):
- patient:read:own
- patient:read:all
- patient:write
- patient:delete
- medical_record:read:own
- medical_record:read:all
- medical_record:write
- appointment:read
- appointment:write
- appointment:delete
- prescription:read
- prescription:write
- prescription:approve (doctors only)
- invoice:read:own
- invoice:read:all
- staff:read
- staff:write
- staff:delete
- clinic:configure
- clinic:delete
- analytics:read
- audit_logs:read
- audit_logs:delete

Role → Permission Mapping:
SUPER_ADMIN: all permissions
CLINIC_ADMIN: all clinic-scoped permissions
DOCTOR: patient:read, medical_record:read/write, appointment:read, prescription:write/approve
NURSE: patient:read, medical_record:read, appointment:read, vital_signs:write
RECEPTIONIST: appointment:read/write, patient:read, check_in:write
PATIENT: patient:read:own, appointment:read:own, appointment:write
BILLING: invoice:read/write, payment:read/write, claims:read/write

MULTI-FACTOR AUTHENTICATION (MFA)
---------------------------------
Optional but Recommended for HIPAA:
- SMS-based OTP (6 digits, 5-minute validity)
- TOTP/Authenticator app (Google Authenticator, Authy)
- Backup codes (10 single-use codes for account recovery)
- Enforce MFA for clinic admins (mandatory)
- Optional MFA for clinical staff

MFA Flow:
1. User enters email + password
2. System validates credentials
3. If MFA enabled, send OTP/prompt authenticator
4. User enters OTP
5. System validates OTP
6. Issue JWT token

PASSWORD POLICY
---------------
✓ Minimum 12 characters
✓ Must include: uppercase, lowercase, number, special character
✓ Cannot reuse last 5 passwords
✓ Expiration: 90 days (reminder at 80 days)
✓ Account lockout: 5 failed attempts → 30-minute lockout
✓ Lockout alerts: Send email on lockout attempt

PASSWORD RESET FLOW
------------------
1. User clicks "Forgot Password"
2. Enter email address
3. System generates 24-hour reset token
4. Send reset link via email
5. User clicks link, enters new password
6. System validates token, updates password
7. All active sessions invalidated
8. User logs in with new password
9. Log password reset event (audit trail)

USER TABLE SCHEMA
----------------
CREATE TABLE users (
  id UUID PRIMARY KEY,
  tenant_id UUID NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  first_name VARCHAR(100),
  last_name VARCHAR(100),
  phone VARCHAR(20),
  status ENUM('active', 'inactive', 'suspended', 'deleted'),
  is_mfa_enabled BOOLEAN DEFAULT FALSE,
  mfa_method ENUM('sms', 'totp', null),
  mfa_phone VARCHAR(20),
  created_at TIMESTAMP,
  updated_at TIMESTAMP,
  last_login TIMESTAMP,
  password_changed_at TIMESTAMP,
  
  -- Constraints
  UNIQUE(tenant_id, email),
  INDEX idx_email (email),
  INDEX idx_tenant_id (tenant_id)
);

CREATE TABLE user_clinic_assignments (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  clinic_id UUID NOT NULL,
  tenant_id UUID NOT NULL,
  is_primary BOOLEAN DEFAULT FALSE,
  assigned_at TIMESTAMP,
  INDEX idx_user_clinic (user_id, clinic_id)
);

SECURITY CONSIDERATIONS
-----------------------
✓ Password Hashing: bcrypt with salt rounds 12 (NOT plain SHA)
✓ Token Signing: RS256 (RSA, not HS256)
✓ Token Storage: HTTP-only cookies for web (not localStorage)
✓ CSRF Protection: SameSite=Strict cookie flag
✓ Rate Limiting: Max 10 login attempts per IP per 5 minutes
✓ Session Tracking: Track active sessions, allow logout from all devices
✓ OAuth2 Scope: Request minimum necessary scopes
✓ API Key Security: For service-to-service, use strong random keys
✓ Token Expiration: Short-lived tokens (15 min) + refresh token rotation
✓ Secure Logout: Invalidate token server-side (Redis blacklist)
✓ Email Verification: Verify email on signup (prevent spam accounts)
✓ Account Recovery: Secure process, time-limited recovery tokens

COMPLIANCE REQUIREMENTS
----------------------
HIPAA:
- ✓ Access logging (who accessed what when)
- ✓ Session logging (login/logout events)
- ✓ Role-based access enforcement
- ✓ Password policies meet HIPAA standards
- ✓ Automatic logout after 15 minutes inactivity
- ✓ MFA strongly recommended
- ✓ No shared login credentials (1 user = 1 login)

GDPR:
- ✓ User can export their authentication data
- ✓ User can delete their account (with clinic approval)
- ✓ Audit trail of all auth events
- ✓ Consent for data processing
- ✓ Right to rectification (update email/profile)

AUDIT LOGGING
-------------
Log all authentication events:
- User login attempt (success/failure, IP, timestamp)
- User logout
- Password change
- Password reset request
- MFA enabled/disabled
- Role changes
- Permission changes
- Failed permission attempts (attempted unauthorized access)
- Session creation/destruction
- Token refresh
- Account lockout

Log Entry Format:
{
  "timestamp": "2024-01-15T10:30:00Z",
  "event_type": "login_success|login_failure|...",
  "user_id": "uuid",
  "tenant_id": "uuid",
  "ip_address": "192.168.1.1",
  "user_agent": "...",
  "details": {...},
  "status": "success|failure"
}
