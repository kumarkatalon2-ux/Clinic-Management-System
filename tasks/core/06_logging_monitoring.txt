BUSINESS LOGIC
--------------
Three Tiers of Logging:

1. APPLICATION LOGS
   - What: Code execution flow, business logic decisions
   - Where: Application files
   - When: Every important operation
   - Example: "Patient created", "Prescription approved", "Payment processed"

2. SYSTEM LOGS
   - What: Infrastructure, OS events, deployment
   - Where: System event logs
   - When: Configuration changes, errors
   - Example: "Database restart", "API deployment"

3. AUDIT LOGS
   - What: WHO did WHAT to WHICH resource at WHAT TIME
   - Where: Audit logging database/service
   - When: All data access and modifications
   - Example: "User john accessed patient John Doe's record"

LOGGING HIERARCHY
-----------------
DEBUG: Detailed debugging information (developers only)
INFO: Informational messages (normal operations)
WARN: Warning messages (potential issues)
ERROR: Error messages (something failed)
CRITICAL: Critical errors (system down, security breach)

STRUCTURED LOGGING FORMAT
--------------------------
All logs should be structured (JSON, not plain text):

```json
{
  "timestamp": "2024-01-15T10:30:00.123Z",
  "level": "INFO|WARN|ERROR|CRITICAL",
  "service": "clinic-api",
  "request_id": "req_abc123xyz", // For tracing
  "logger": "PatientService",
  "message": "Patient record created",
  "event_type": "patient.created",
  
  // Context
  "user_id": "user-123",
  "tenant_id": "clinic-001",
  "ip_address": "192.168.1.1",
  "user_agent": "Mozilla/5.0...",
  
  // Resource
  "resource_type": "patient",
  "resource_id": "patient-456",
  "resource_changes": {
    "before": {...},
    "after": {...}
  },
  
  // Performance
  "duration_ms": 245,
  "database_queries": 3,
  
  // Error info (if applicable)
  "error_code": "VALIDATION_ERROR",
  "error_message": "Email already exists",
  "stack_trace": "..."
}
```

LOG RETENTION POLICY
--------------------
Compliance Requirements:

HIPAA:
- Audit logs: Minimum 6 years retention
- Access logs: Minimum 6 years retention
- Error logs: Minimum 2 years retention

GDPR:
- Processing audit: Minimum 3 years
- Consent logs: Minimum 3 years
- Data subject audit: Keep with retention period

Recommendation:
- Hot storage (accessible): 90 days
- Warm storage (archive): 90 days - 1 year
- Cold storage (tape): 1 year - 6 years
- Compliance retention: 6+ years

STRUCTURED LOGGING LIBRARIES
----------------------------
Recommended tools:
- Backend: Winston (Node.js), Serilog (C#), Logback (Java)
- Format: JSON to stdout
- Collection: Fluentd, Logstash, Beats
- Storage: ELK Stack (Elasticsearch), Splunk, CloudWatch, Datadog
- Analysis: Kibana, Splunk UI

Example (Node.js + Winston):
```javascript
const logger = winston.createLogger({
  format: winston.format.json(),
  transports: [
    new winston.transports.File({ filename: 'error.log', level: 'error' }),
    new winston.transports.File({ filename: 'combined.log' })
  ]
});

logger.info('Patient created', {
  resource_type: 'patient',
  resource_id: patientId,
  user_id: userId,
  tenant_id: tenantId
});
```

ALERTING STRATEGY
-----------------
Set up alerts for critical events:

CRITICAL ALERTS (page on-call):
- API down (uptime < 95% in 1 minute)
- Database connection pool exhausted
- Authentication service unavailable
- Disk space < 5%
- Security breach detected (repeated auth failures)
- PII data export detected

URGENT ALERTS (notify team):
- Error rate > 5% for 5 minutes
- Response time p95 > 5 seconds
- Database replication lag > 30 seconds
- Audit log ingestion backlog > 10k
- Failed backups

INFORMATIONAL ALERTS (dashboard only):
- Daily summary of events
- Performance trends
- Usage reports

Example Alert:
```
CRITICAL: API Error Rate Spike
Timestamp: 2024-01-15 10:30:00 UTC
Error Rate: 15% (threshold: 5%)
Requests: 10,000
Errors: 1,500
Most Common Error: DATABASE_CONNECTION_TIMEOUT
```

DISTRIBUTED TRACING
-------------------
For debugging multi-service calls:

Trace ID: Follows request through entire system
Span ID: Individual operation within trace
Parent Span ID: Links to parent operation

Example Flow:
1. User calls GET /api/v1/patients/123
   - Trace ID: trace_abc123
   - Span: api_gateway (100ms total)
   
2. API calls database
   - Parent Span: api_gateway
   - Span: db_query_patient (80ms)
   
3. API calls cache
   - Parent Span: api_gateway
   - Span: cache_lookup (5ms)

Tools: Jaeger, Zipkin, Datadog APM

REQUEST ID TRACKING
-------------------
Every request gets unique ID for tracing:

1. Client sends request (or system generates)
2. Request ID added to all logs from that request
3. Response includes Request ID header
4. Client can use for support tickets
5. Support can search all logs for request ID

Header:
```
X-Request-ID: req_abc123xyz
```

Response header includes:
```
X-Request-ID: req_abc123xyz
```

GDPR & HIPAA COMPLIANCE LOGGING
-------------------------------
Specific logging requirements:

GDPR Data Subject Access Request:
- Log all data accessed for subject
- Log all data shared with third parties
- Log all uses of data
- Keep for 3 years minimum

HIPAA Minimum Necessary:
- Log who accessed what (and justify need)
- Log date, time, user, resource, action
- Log unauthorized access attempts
- Log all administrative actions

Consent Tracking:
- Log when consent obtained
- Log consent version
- Log consent revocation
- Log data processing after consent

LOG AGGREGATION ARCHITECTURE
----------------------------
Flow:
1. Application logs to stdout (JSON)
2. Log shipper (Fluentd) collects
3. Fluentd parses and enriches
4. Sends to Elasticsearch
5. Kibana provides interface
6. Alerts trigger from rules

OR

Cloud solution (simpler):
1. Application logs to CloudWatch/Datadog
2. Automatic parsing
3. Dashboard/alerts included
